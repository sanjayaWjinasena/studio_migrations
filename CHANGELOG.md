**Changed:**
- **Metadata**: __manifest__.py (version bump)

**Message:**
> fix(v0.0.2): add BugFix-Sales dep so related-chain resolves at load time
>
> account.move.x_studio_bank_guarantee_approved is declared as
>   related='x_studio_sale_id.x_studio_bank_guarantee_approved'
> with store=True. The walk needs sale.order.x_studio_bank_guarantee_approved
> to exist at Python setup_related() time.
> sale.order.x_studio_bank_guarantee_approved is declared by BugFix-Sales
> (v30+, state=base). Before this fix studio_migrations only depended on
> 'sale' — so studio_migrations loaded BEFORE BugFix-Sales, and setup_related
> crashed with:
>   KeyError: 'Field x_studio_bank_guarantee_approved referenced in related
>   field definition account.move.x_studio_bank_guarantee_approved does not
>   exist.'
> Adding BugFix-Sales to depends forces the load order:
>   sale -> BugFix-Sales -> studio_migrations
> so the related walk resolves cleanly.
